# Code Review Guide

每次对代码、配置或本仓库资源做出变更（含 AI 生成的变更）前，按此清单自查；给他人 review 时也按此清单逐项核对。

## 变更前

- **影响面**：明确变更触及哪些模块/工具/文件；涉及共享配置（MCP、hooks、env、teamai.yaml）时，说明对已安装工具的影响。
- **词汇一致**：涉及本仓库领域概念时，使用 `CONTEXT.md` 的规范术语；引入新概念先补词表再使用。
- **安全性**：不引入凭证泄漏（API key、token 不落库、不写进配置明文）；不破坏既有用户配置（未要求覆盖的内容保持原样）。

## 变更后

- **验证**：可运行验证的必须实际运行（`teamai doctor`、测试、构建）；无法验证的说明原因与验证缺口。
- **文档同步**：行为变化同步更新 README / docs / learnings；难逆转的决策记入 `docs/adr/`。
- **最小变更**：只提交任务要求的改动；格式化、重构与任务无关的内容分开提交。

## 仓库资源变更特例

- 修改 `skills/`、`rules/`、`mcp/`、`env/` 后必须跑 `teamai doctor` 确认资源仍可被工具发现。
- 删除资源用 `teamai remove` 流程（经 push 生效），不留孤儿引用。
