# Session：teamai-cli 教学 Session（teach skill）

## 发生了什么
使用 "teach" skill 从团队管理员视角系统学习 teamai-cli。创建了一个结构化教学 workspace，包含 5 节课，覆盖完整管理员工作流。

## 关键学习

### teamai-cli 作为团队协作层
- Skills、rules、hooks、MCP、env 都存放在共享 Git repo 中
- push → MR → pull 流程把配置分发给所有团队成员
- SessionStart hook 在每个 AI session 自动拉取最新团队配置

### 仓库结构
- `skills/` = 按需、按场景触发（带 YAML frontmatter：name、description、tags）
- `rules/` = 始终生效的约束，注入每个 session
- `agents/` = 自定义 AI 角色（YAML）
- `hooks/hooks.yaml` = 生命周期钩子（SessionStart、Stop、PreToolUse）
- `culture.md` = 始终注入的团队价值观
- `env/` = 共享变量（**不能放 secrets**）
- `teamai.yaml` = repo 元数据、npm 包、recall 默认配置

### 分发流水线
1. 角色命名空间扩展（primaryRole + additionalRoles → 命名空间集合）
2. 标签订阅叠加（跨命名空间的 skill 订阅）
3. 排除列表过滤（个人排除项，`teamai skill exclude`）
4. 最终同步到本地 AI 工具

### 角色系统
- 管理员通过 `teamai roles add <id> --namespaces a,b,c` 定义角色
- 成员通过 `teamai roles set <id>` 选择角色
- 安全降级：若管理员删除一个角色，会自动回退到全量同步并给出警告
- push 时带 `--role` 参数：只针对某个命名空间发布

### 知识管理
- Recall 默认关闭 — 必须通过 teamai.yaml 或 `teamai recall enable` 显式启用
- Learnings 通过摩擦评分自动捕获（interrupt、toolReject、correction、retries）
- 从仓库/组织/MR 导入：`teamai import`
- 代码库知识图谱：tree-sitter AST + 启发式提取
- 维护循环：prune → archive → update-quality

### 管理员日常节奏
| 频率 | 操作 |
|-----------|--------|
| 每周 | `teamai digest` |
| 每周 | `teamai recall maintenance --prune --dry-run` |
| 按需 | `teamai recall promote <id>` |
| 按需 | 推送新 skills / rules |
| 每季度 | `teamai recall maintenance --update-quality` |
